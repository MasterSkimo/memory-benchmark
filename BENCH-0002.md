# BENCH-0002 — Semantic and agentic memory comparison

Parent: BENCH-0001 PR #1, commit `94a2a4beacf90f6a9640ecd43ebae8b8c9e7a708`. **Preserve BENCH-0001 results unchanged.**

## Objective

Establish whether real semantic/graph memory improves grounded answers and reduces native Luna tool calls/tokens versus scoped direct Markdown, at equivalent answer quality. The prior pilot compared mostly lexical/non-neural retrieval and did not measure per-question native tokens.

## Execution contract

1. Read AGENTS.md, BENCH-0001.md, WORKER-CONTRACT.md, BENCH-0001 reports and ADR. Use native Codex SOL as coordinator and native Luna workers. Do not use nested authenticated Codex CLI, OpenRouter or paid external APIs.
2. Start with environment check capped at 10 minutes; implement rather than reporting only blockers. Do not bypass HTTP proxies or platform security.
3. Delegate independent workers: (a) Cognee tokenizer/offline assets and real ingestion, (b) Basic Memory MCP compatibility, (c) Graphiti genuine extraction/temporal graph, (d) Qdrant real local embeddings + sparse retrieval, (e) benchmark harness and direct Luna baseline. Keep candidate source and outputs isolated by path/worktree.
4. Fix tokenizer 403 via legal package cache/preprovisioned static tokenizer assets or supported offline configuration. Pin checksum/version; do not fetch from forbidden endpoint through alternate proxy. If not feasible, record a reproducible blocker and continue.
5. Choose and pin a common **local** multilingual embedding model for applicable semantic candidates, with exact revision, dimensions, normalization and cache. Do not substitute deterministic hashing vectors as semantic embeddings. Graphiti/Cognee extraction needs a documented local LLM, if supported. Separate extraction quality/cost from retrieval quality.
6. Use an immutable, withheld test set generated by an independent evaluator **after** workers freeze their implementations; do not make expected answers visible to candidate workers before answers are submitted. Keep training/dev examples public. A holdout is only valid if the evaluator has an actual access boundary; otherwise label it non-blind and do not claim unbiased generalization.
7. Expand evaluation beyond the four repeated projects: paraphrases with low lexical overlap, multi-hop relationships, conflicting/obsolete decisions, negative/abstention, revision changes and cross-project attempts. Include difficult French and English questions. Keep fixed scope/authorization and document citations/revisions.
8. Run two separate lanes: retrieval top-k=5 (recall, precision, MRR, obsolete hits, negative empty-hit rate, p50/p95, setup/index time, CPU/RAM, I/O) and Luna end-to-end grounded answers for **every runnable candidate** using equivalent tools/prompt/model/effort and fresh sessions. Do not compare direct Luna E scores against other engines' retrieval-only scores.
9. Capture real native input/output/cached/reasoning tokens and tool events only if supported; if not, report null and an instrumentation coverage matrix. Do not infer subscription costs from token estimates. Record wrapper calls separately from native tool calls. If native E parity cannot be enforced, mark comparisons exploratory, not causal.
10. Backend security: enforce trusted-principal-bound org/project scope before search and after result mapping. Test forged question scope, document metadata, paths, tenant filters and stale revisions. Do not accept prompt-based access control as security.
11. Run real integration/E2E tests; avoid enormous suites of tiny unit tests. Freeze dependency versions, source SHA, corpus hashes, prompts and run manifests. Preserve BENCH-0001 traces and report v1/v2 separately.
12. Limit to a **small V2 semantic pilot** (target 40 diverse questions, 8+ per category where feasible) and at most 20 E answers per candidate until review. Do not run full 190 or load testing without approval. No unapproved paid spend.
13. Output `results/v2/COMPARISON.md`, `results/v2/run-manifest.json`, `ADR-0002-semantic-memory.md`, code and tests. State exactly which engines were genuinely exercised and where dependencies remain blocked. Open a new PR against `codex/bench-0001-real-pilot`, not main; do not merge PR #1 or alter its historical results.

## Success criteria

At least one true semantic retrieval engine runs end-to-end with local embeddings, with reproducible integration evidence. Cognee and MCP Basic Memory must either be repaired or have exact stage-specific blockers. No invented quality, model telemetry, or token savings. Stop after V2 pilot for review.
